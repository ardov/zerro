# Local predictions

A command contains primary intent. Core expands it against the latest snapshot and predicts server effects so balances and lists update immediately. Transport separately expands primary intent. Canonical responses already contain server effects and go straight through patch application. [Change pipeline](architecture.md#change-pipeline)

| Change                                                | Local result                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Edit a soft-deleted transaction                       | Ignore the patch. Restoring creates a new ID.                                                                                                                                                                                                                                                                             |
| Both transaction amounts below `0.00005`              | Purge the row. The wire operation on a canonical row uses small positive amounts because literal zero/zero is rejected. An intermediate locally created and purged row absent from the canonical base is omitted from transport.                                                                                          |
| Change an account's starting balance or a transaction | Apply the difference in starting balance and active income/outcome legs to the affected accounts.                                                                                                                                                                                                                         |
| Delete an account                                     | Purge live transactions wholly inside deleted accounts. With an ordinary surviving account, keep the transfer on that account and zero its removed leg. With a surviving debt account, soft-delete the transaction, null the removed account leg and keep both amounts. Already deleted rows are outside this prediction. |
| Delete a tag                                          | Clear child-parent and category references, retain surviving tags and remove the keyed budget rows.                                                                                                                                                                                                                       |
| Delete a merchant                                     | Clear merchant and payee on ordinary linked rows, preserving transaction original payee. Active debt transactions protect the merchant. When its linked debt row is already soft-deleted, deletion can purge that row.                                                                                                    |
| Rename a merchant                                     | Update the merchant. Reads resolve its new title immediately. Zenmoney sends linked transaction payee changes with canonical data.                                                                                                                                                                                        |

Balance prediction uses each leg in its account currency, including future and held transactions. Deposit and loan accounts use a zero opening term. Original-purchase amounts, credit limits and currency conversion do not enter the delta. Replay computes it against the new base to avoid applying it twice. The transaction list's visibility threshold (`0.0001`) is separate from the server purge threshold.

For a prediction change, test the applied patch, resulting state and primary-only transport. Cover repeated writes and mixed batches, using an observed server fixture where available.
